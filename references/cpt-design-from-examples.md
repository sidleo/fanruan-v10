# 从本地 Demo 提炼 CPT 设计技巧

适用：已经有一批本地 `.cpt` 样例，希望学习报表选型、信息层级、版式、表格、图表、
交互和适配规则，再把这些手法用于新报表或已有报表改造。全程只读样例，不需要连接实例。

这份文档解决「为什么这样设计」和「怎样比较样例」。具体 XML 契约、命令语法和复现配方分别见
`cpt-xml.md`、`cpt-authoring.md`、`cpt-patterns.md`、`cpt-patterns2.md`。

## 1. 学习产物必须是一份可实施的设计结论

读完 Demo 后，至少要能写出下面这些内容；只有文件清单或几个标签不算完成：

1. 业务决策是什么，读者看完后要做什么。
2. 选择哪种报表原型，为什么；哪些原型的收益更低。
3. 信息按什么顺序出现：范围、筛选、指标、主视图、补充视图、明细、口径说明。
4. 数据粒度和扩展方向是什么，合计与小计分别表达什么。
5. 字号、颜色、数字格式、对齐、边框和条件属性各承担什么语义。
6. 哪些交互是必需的主路径，哪些只是样例中的附加能力。
7. 将每个手法映射到哪条 `frcli report ...` 命令。
8. 用哪些预览、导出和数据对账步骤证明它真的有效。

要提炼「手法」，不要整张复制。样例中的数据连接、业务字段、品牌配色、参数名和特例阈值通常不可复用。

## 2. 推荐工作流

### 2.1 先把业务问题写成设计约束

先确定以下信息，再打开样例：

| 约束 | 需要明确的内容 |
|---|---|
| 决策 | 看完报表要发现什么、比较什么、采取什么动作 |
| 读者 | 管理层、业务人员、审核人员、录入人员或外部客户 |
| 粒度 | 每行是一条明细、一个分组、一个汇总，还是二维交叉汇总 |
| 渠道 | 浏览器、手机、PDF、Excel、Word、CSV、打印或大屏 |
| 规模 | 行数、列数、维度基数、数据集延迟和刷新频率 |
| 动作 | 只看、筛选、排序、钻取、联动、录入、审核或导出 |
| 口径 | 时间范围、单位、币种、精度、空值、合计和排名规则 |

同样一张分组表，用于逐行审核、打印归档和移动端概览，密度与交互会完全不同。

### 2.2 批量画像，先找同类问题

```bash
# 先看整库有哪些原型和设计技术
frcli report local-profile "<reportlets目录>" -n 20

# 按报表原型或技术标签筛同类样例
frcli report local-profile "<reportlets目录>" --tag grouped-table -n 10
frcli report local-profile "<reportlets目录>" --tag dashboard -n 10
frcli report local-profile "<reportlets目录>" --tag form -n 10
frcli report local-profile "<reportlets目录>" --tag chart-linkage -n 10
frcli report local-profile "<reportlets目录>" --tag split-columns -n 10

# 再用路径关键词缩小业务类型
frcli report local-profile "<reportlets目录>" --keyword 销售 --tag crosstab -n 10
```

`--tag` 同时接受原型标签和技术标签。结果中的 `archetypes` 是整份模板呈现的主要报表形态，
`techniques` 是实现手法。一个样例可以同时属于多个原型。

`study_score` 是检索排序分，不是设计质量分；按标签检索时，它先确认目标结构完整，再优先规模小、
附带控件/脚本/多 sheet 较少的样板。目标技术达到足够数量后不再无限加分，超大综合模板不会仅因
能力多就压过基础样板；`score_semantics` 会明确这一边界。`study_points` 是单份模板的初步学习提示；
`design_lessons` 汇总整库中每类技术的可执行建议和命中样例数。两者仍需回到单元格和预览中核对。

`design_lessons` 的频率只用来决定先研究哪些常见手法，不能证明某手法适合当前决策；
低频技术也可能是当前任务的关键，例如图表联动或手机表单。

常用原型标签：

| 标签 | 含义 |
|---|---|
| `detail-table` | 逐行明细 |
| `grouped-table` | 有分组或小计的表 |
| `crosstab` | 横纵两个方向同时扩展的交叉表 |
| `chart-analysis` | 以图表为主要表达手段 |
| `master-detail` | 概览、主表或图表通过跳转进入更细数据 |
| `dashboard` | 多指标、多图表或指标卡组合的概览页 |
| `form` | 有输入控件和写入提交的真实填报表单 |
| `aggregate-layout` | 聚合报表；多个 Block 各自拥有独立网格 |
| `static-layout` | 说明、封面、规则或图文静态页 |

常用技术标签包括 `group-subtotals`、`multi-dataset`、`formula-calculations`、
`conditional-formatting`、`linked-report`、`chart-linkage`、`frozen-report-area`、
`frozen-control-panel`、`floating-layout`、`split-columns`、`custom-javascript`、
`number-formatting`、`color-coding`、`chart-<类型>`。

### 2.3 选 3–5 个可比较的样板

不要只看 `study_score` 第一名。优先组成一组互补样板：

1. **基准样板**：业务问题最接近、结构最简单。
2. **信息增强样板**：同一问题增加了分组、合计、图表或注释。
3. **高密度样板**：用于观察列顺序、冻结、分页和条件高亮。
4. **交互样板**：用于观察筛选、钻取、图表联动或提交。
5. **渠道样板**：手机、打印、Excel 或大屏中与目标最接近的一份。

每个样板都要记录「保留什么」和「不采用什么」。高复杂度模板只能证明某种组合能工作，
不能证明它适合当前业务。

### 2.4 先读整份画像，再看关键单元格

```bash
frcli report local-inspect "<reportlets目录>/<样例>.cpt" --design
frcli report local-inspect "<reportlets目录>/<样例>.cpt" --sheet "<sheet名>" --cells -n 200
frcli report local-inspect "<reportlets目录>/<样例>.cpt" --sheet "<sheet名>" --block 2 --cells
```

阅读顺序：

1. `archetype` / `archetypes`：模板实际承担哪些报表任务。
2. `layout`：sheet、Block、浮动元素、分栏、冻结区、绝对布局。
3. `data`：数据集数量、参数、绑定格、公式、横纵扩展、分组/列表/汇总、合并格。
4. `visual`：字体、字号、颜色、数字格式、对齐、边框、条件属性。
5. `interaction`：控件、提交、超链接、图表联动、JavaScript。
6. `charts`：图表数、类型、标签和提示。
7. `--cells`：确认具体格号、扩展方向、数据设置和条件规则。

聚合报表的每个 Block 都有自己的 `A1`。比较时保留 `block_index` 和 `block_name`，不要把所有块拼成一张网格。

### 2.5 把观察转换成设计规则

对每个样板记录下面八项，最终取交集与差异：

| 观察项 | 要回答的问题 |
|---|---|
| 页面任务 | 这一页只解决哪个问题 |
| 信息顺序 | 读者第一眼、第二眼、第三眼分别看什么 |
| 数据粒度 | 行、列和汇总值分别表示什么 |
| 空间结构 | 网格、Block、浮动元素、分栏、绝对布局为何这样选 |
| 表格语义 | 哪个格负责分组、列表、明细、汇总、排名或占比 |
| 视觉语义 | 颜色、数字格式和条件属性如何对应业务状态 |
| 交互主路径 | 用户从概览到明细最少要几步 |
| 渠道约束 | 屏幕、手机、打印和导出分别牺牲了什么 |

只保留 3–7 条能够指导当前报表的规则。样例之间冲突时，以当前决策、数据粒度和交付渠道为准。

## 3. 从业务问题选择报表原型

| 业务问题 | 首选原型 | 推荐结构 | 不应使用它的场景 |
|---|---|---|---|
| 逐笔核对、异常追查、导出后继续加工 | `detail-table` | 稳定列顺序 + 数字格式 + 条件高亮 + 明确总数 | 管理层只需要少数汇总结论 |
| 按层级组织数据并在组内小计 | `grouped-table` | 父组、子项、正确的小计位置、可折叠或跳转 | 两个维度需要同权比较 |
| 同时比较两个维度的组合结果 | `crosstab` | 行维向下扩展、列维横向扩展、值汇总 | 任一维度的基数过大到无法扫读 |
| 趋势、分布、结构或关联 | `chart-analysis` | 一个主问题一张主图，少量辅助图 | 需要逐行核对精确数值 |
| 从总览进入目标明细 | `master-detail` | 主视图 + 参数传递 + 目标页 + 返回上下文 | 概览和目标数据粒度未对齐 |
| 一屏扫描多个关键结论 | `dashboard` | 范围标题 + 3–6 个 KPI + 主图 + 2–4 张补充视图 + 钻取 | 把完整明细表塞进一屏 |
| 录入、校验、暂存和提交 | `form` | 输入控件 + 校验 + 默认值 + 提交 + 成功/失败反馈 | 只读分析或批量浏览 |
| 多块异构版面、卡片、特殊标题区 | `aggregate-layout` | 每个 Block 独立负责一种内容与坐标 | 普通线性表格就能完成 |
| 说明、封面、规则、图文叙事 | `static-layout` | 标题、正文、图示、口径、版本信息 | 有实时取数或操作诉求 |

先看数据形状，再看视觉效果。错误的原型无法靠配色补救。

## 4. 企业报表信息层级

默认从上到下组织：

1. **标题与范围**：报表名、组织/对象范围、时间范围、更新时间、单位。
2. **驱动筛选**：只保留会改变结论的 2–5 个筛选器；默认值必须表达一个合理业务范围。
3. **摘要指标**：3–6 个 KPI，给出值、单位、比较基准和方向；不要用十几个同等醒目的数字。
4. **主决策视图**：一个主表或主图，回答最重要的问题。
5. **补充视图**：用于拆解、比较、异常定位或趋势验证。
6. **明细与钻取**：按需展开；明细列顺序跟随核对路径。
7. **口径与注释**：单位、计算式、空值规则、更新时间、异常说明和操作提示。

同一语义只出现一次。标题、页眉、KPI 和表尾不要各自重复一遍相同的总数。

### 4.1 宽表与长表

- 列数多但每列都会参与核对时，使用宽明细表，并冻结关键标识列和标题行。
- 行列组合过多时，改成“筛选 + 少量核心列 + 钻取”，不要无限横向扩张。
- 需要打印时，把不可拆分的标识与关键值放在同一视觉组；窄列不要承载长注释。
- 需要 Excel 二次加工时，保持一列一字段、一个表头层级和稳定数据类型。

### 4.2 分组、小计与总计

- 分组表解决层级；交叉表解决二维比较；明细表解决逐行事实。三种语义不要混在一格。
- 小计属于父组，总计属于整张表；只有业务明确要求时才同时展示。
- 数值列先确定聚合方式再排版；空值、除零和重复计数必须有明确规则。
- 分组后隐藏明细列，应确认隐藏的是展示而非底层计算依赖。

## 5. 视觉规则

### 5.1 字体与字号层级

使用一套字体和少量字号层级：报表标题、区块标题、正文/表头、辅助说明。字号差异应与信息层级一致，
不要靠粗体和颜色同时强调所有层。

可从以下范围起步，再按企业规范和渠道调整：

| 层级 | 常见起始范围 |
|---|---|
| 报表标题 | 16–20 pt |
| KPI 数字 | 22–32 pt |
| 区块标题 | 12–15 pt |
| 表头与正文 | 9–11 pt |
| 注释/单位 | 8–9 pt |

手机端优先减少字号层级，避免把桌面全页简单缩小。

### 5.2 颜色必须有固定职责

采用有限调色板，并保持同一含义跨页一致：

- 中性色：背景、边框、普通文字。
- 品牌/主强调色：主视图或关键动作。
- 正向色：达标、增长或正常。
- 警示色：异常、超阈值或需要处理。
- 禁用/弱化色：非当前筛选或低优先级信息。

条件属性的阈值来自业务规则，不来自“看起来醒目”。不能只用红绿区分状态；同时使用文字、图标或数值方向。

### 5.3 数字、日期和对齐

- 数量、金额、比例、百分点和日期使用不同格式。
- 同一列统一单位和小数位；单位写在表头、标题或固定注释中。
- 数值右对齐，短标签居中，说明文字左对齐。
- 百分比明确是 `0.15` 还是 `15%`，避免公式正确但显示口径错误。
- 合计和明细使用一致的小数位；四舍五入差异要有解释。

### 5.4 边框、留白与合并格

- 用留白和少量分隔线分组，不为每个单元格加同强度边框。
- 合并格只表达跨列标题、度量组或说明，不用于制造无法排序和导出的伪结构。
- 表头层级应能回答“这一列属于哪个组”，但不能超过目标渠道的阅读宽度。
- 报表密度由业务动作决定：核对页可紧凑，概览页应减少同时出现的数字。

## 6. 图表选择规则

| 表达目的 | 首选 | 约束 |
|---|---|---|
| 类目排名、长标签比较 | 条形图 | 按值排序；避免标签旋转后难读 |
| 少量类目比较 | 柱形图 | 类目过多时改为排名前 N + 其他 |
| 连续时间趋势 | 折线图 | 时间间隔一致；少用多个不同量纲系列 |
| 单一时点的部分与整体 | 饼图/环形图 | 只保留最多约 5–7 个有意义的切片 |
| 多个构成随时间变化 | 堆积面积图或百分比堆积图 | 确认读者关心总量还是结构 |
| 两个连续变量的关系 | 散点图 | 标明离群值、相关性和样本量边界 |
| 多个维度与规模 | 气泡图 | 气泡面积与数值关系要可解释 |
| 地理分布 | 地图 | 只在地理位置本身有决策价值时使用 |
| 单 KPI 与目标进度 | 仪表盘 | 只用于少量目标；不能替代趋势和明细 |
| 项目阶段与时间 | 甘特图 | 必须统一时间轴、任务层级和里程碑 |
| 流程转化 | 漏斗图 | 阶段必须连续且同一业务漏斗 |

一张图只回答一个主问题。图表标题写结论或明确范围，轴、图例、标签、提示和空数据状态都要验收。
组合图只在单位、颜色和主次关系清楚时使用，不能把多个无关指标叠在一起制造“丰富感”。

## 7. 交互规则

### 7.1 筛选

- 只让筛选器改变依赖它的数据区域；不相干模块不要一起刷新。
- 默认值要有业务意义，并让用户能识别当前范围。
- 参数名、控件名和模板参数必须对齐；联动与提交无法靠导出产物验收。

### 7.2 钻取与超链接

- 每次跳转至少传递时间、组织、对象和当前筛选上下文。
- 目标报表只接收驱动参数；派生参数按目标模板推导。
- 预留返回路径和空结果提示。
- 优先用报表超链接完成任务；JavaScript 只在原生能力不足时使用。

### 7.3 图表联动与详情

- 联动控件要明确触发方式、选中态、清除态和空数据状态。
- 联动后的图表标题和筛选提示必须变化，否则读者不知道当前看的是什么。
- 图表点击进入明细时，核对点击值和明细查询条件使用同一口径。

### 7.4 冻结

- 长表滚动时冻结关键标识列和表头；屏幕、手机和打印分别检查。
- 固定控件区只固定真正需要反复操作的控件，避免挤压小屏内容。

### 7.5 表单

- 输入顺序跟随业务任务，而不是数据库字段顺序。
- 写明必填、格式、范围和联动规则；提供默认值与错误反馈。
- 提交前防重复，提交后显示结果；暂存与正式提交要语义分离。

## 8. 渠道适配

| 渠道 | 设计重点 | 应避免 |
|---|---|---|
| 浏览器预览 | 筛选、联动、钻取、滚动和冻结完整可用 | 只看导出图，不看交互 |
| 手机 | 单列信息流、卡片、少量筛选、主视图优先、触控尺寸稳定 | 把桌面宽表整体缩小 |
| PDF | 固定纸张、页面方向、重复表头、页脚页码和不可拆分组 | 浮动元素遮挡、超宽表 |
| Excel | 一列一字段、表头稳定、数值类型正确、打印区明确 | 依赖悬浮图形表达核心数据 |
| Word | 适合说明与少量表格，分页和表格宽度受目标模板影响 | 超宽明细表 |
| CSV | 只表达扁平数据，保留稳定列名和原始值 | 颜色、合并格、图表、交互 |
| 大屏/驾驶舱 | 远距离可读、指标少而有层级、更新时间清晰 | 高密度明细和多层筛选 |

绝对布局适合明确屏幕尺寸的驾驶舱和表单，但不是打印或响应式默认方案。使用前先确定目标分辨率、
最小宽度、滚动规则和导出要求。

## 10. 从样例手法映射到 CLI

| 已识别的设计手法 | 实施入口 |
|---|---|
| 新建模板、数据集、参数 | `report new` / `report dataset` / `report param` |
| 标题、公式、绑定、扩展、数据设置、合并 | `report cell` |
| 标准表头与逐列绑定 | `report table` |
| 交叉表 | `report crosstab` |
| 分组小计、占比、环比、同比、累计 | `cpt-patterns.md` 的配方 + `report cell` |
| 颜色、数字格式、边框、对齐 | `report style` / `report cell --style/--num-format` |
| 条件属性、异常高亮、数据条 | `report highlight`；完整表达式见 `cpt-patterns.md` |
| 图表 | `report chart`；模型细节见 `cpt-patterns2.md` |
| 参数控件 | `report widget` |
| 钻取、网页链接、JavaScript | `report link` |
| 重复标题、页脚页码、冻结、分页 | `report page` |

聚合报表的各个 Block 使用独立坐标。frcli ≥ 0.11.0 可对已支持的网格块执行编辑：
先用 `report local-inspect TEMPLATE.cpt --cells` 确认块序号与类型，再明确 `--sheet S --block N`
（N 为工作表内块的 1 基序号）。支持命令见 [本地示例检查](cpt-local-examples.md#聚合报表每个区块都有自己的网格)；

## 11. 验收顺序

### 11.1 结构回读

- `report cell --list`：格号、绑定、数据设置、扩展、公式、样式和合并。
- `report dataset --list`：连接、SQL、参数和数据集数量。
- `report crosstab/highlight/page/chart/widget/link --list`：对应对象是否真实写入。
- `report local-inspect --design`：对本地模板再做一次独立画像，确认原型和技术没有意外改变。

### 11.2 数据对账

- 选最少一组手算样例，核对明细、分组、小计、总计和占比。
- 检查筛选前后的行数与总额变化。
- 检查空值、重复值、除零、日期边界和最大维度。
- 确认报表显示单位与公式单位一致。

### 11.3 预览验收

以下能力只能在预览或真实交互中确认，导出通常看不出来：

- 参数控件、联动、钻取、图表点击、冻结、滚动和提交。
- 手机布局、触控目标、滚动区和不同窗口宽度。
- JavaScript 的默认状态、幂等、异常恢复和降级。

### 11.4 导出验收

- 导出文件先校验魔数，不能把 HTML 出错页当报表。
- PDF 检查分页、重复表头、页脚页码、不可拆分组和颜色可读性。
- Excel 检查单元格值、类型、数字格式、合并区域、打印区和实际列宽。
- Word 检查表格宽度、分页和图片嵌入。
- CSV 只检查扁平数据和列名，不期待样式与交互。

### 11.5 跨渠道一致性

同一口径在浏览器、PDF、Excel 和手机中至少抽一组相同范围核对。交互能力可以不同，
业务数值和筛选范围不能不同。

## 12. 常见反模式

- 按文件名找到一个大而全的 Demo，就直接复刻整张版面。
- 把 `study_score` 当成设计评分，忽略业务适配。
- 看到图表多就判断是驾驶舱；多个图表可能只是并列分析页。
- 为了“高级感”使用绝对布局，最后无法适配手机或打印。
- 用饼图展示几十个类目，或用仪表盘展示所有指标。
- 多个数据集直接拼在一页，没有先对齐粒度、时间和连接键。
- 条件颜色没有业务阈值，所有异常都用同一种红色。
- 交叉表、分组表和明细表的汇总语义混用，重复计算总计。
- 表单只有输入框，没有必填、校验、提交反馈和重复提交保护。
- 钻取只跳转页面却不传递当前筛选，返回后上下文丢失。
- 用 JavaScript 实现原生超链接、控件或冻结能完成的事情。
- XML 画像看起来正确就交付，没有预览、数据对账和导出验收。
