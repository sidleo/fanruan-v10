# 发布与脱敏流程

> 本仓库（`fanruan_v10`）是 skill 的**唯一目录**，且**可能公开**，因此必须始终保持"脱敏"状态。
> 记录真实环境值（服务器、账号、目录、连接名、工号、报表名）的地方是**知识库 llm-wiki**，不是本仓库。

## 一、原则：只写能力，不写环境

| 该写 | 不该写 |
|---|---|
| 命令怎么用、XML 怎么写、坑点是什么 | 你的服务器地址、账号、工号 |
| 用占位符举例（`demo_group/…`、`demo_conn`） | 真实报表目录、真实连接名、真实报表名 |
| 与机器无关的判据（"若 X 则 Y"） | "本机装了…""我的安装目录是…" |

安装目录用 `$FINEREPORT_HOME` 这类**环境变量**表达（见 `src/frcli/rpc_catalog.py`），
不写死绝对路径 —— 这样能力照旧、环境信息为零。

## 二、黑名单（每次发布前逐项复扫，必须全 0）

人（姓名）｜工号（8 位数字，常出现在连接名里）｜服务器域名｜SSO 域名｜公司名/域名｜
报表目录（含部门名）｜数据库连接名｜业务组织名｜生产报表文件名｜内部指标全称。

## 三、三个必须扫的地方（漏一个就等于没做）

1. **工作树文本** —— 含 `.md/.py/.sh/.toml/.cpt/.csv/.html/.json/.txt`（**别只扫 .md/.py**：
   实测漏过一次 `.cpt`，里面的 `<DatabaseName>` 带着真实连接名）。
2. **二进制产物** —— `.skill` 包是 zip，**grep 扫不到内部文本**；必须解包后再扫。
   工作区若残留渲染产物（PNG/PDF/XLSX），注意**服务端渲染会带个人水印**（姓名+工号）与真实数据，**一律不进仓库**。
3. **git 历史** —— 仓库一旦公开，`git log -p` 能看到**每一条历史提交**。改工作树不够，
   要用 `git filter-branch --tree-filter` 逐提交重写，然后**逐 blob 复扫**（含把历史里的 zip 解包再扫）。

## 四、发布流程（一条命令）

黑名单放在**仓库外**：`~/.frcli/redact-blacklist.txt`（一条一行的正则）或 `$FRCLI_REDACT_BLACKLIST`。
两者都没有时脚本**拒绝运行**（fail-closed）—— 因为黑名单本身就是真实值，不能进仓库。

```bash
tools/build_skill.sh --check     # 只复扫：工作树 / 包内(解开 zip) / git 历史
tools/build_skill.sh             # 复扫通过后打包到 dist/fanruan-v10.skill
tools/build_skill.sh --check     # ⚠️ 必须再来一次：② 扫的是"当前 dist 里的包"，
                                 #    第一次 --check 时里面还是上一次的旧包；这一步才扫到刚打的这一个
git add -A && git commit -m "<版本>：..." && git push
```

`dist/fanruan-v10.skill` **要入库**（它是交付物）：`.gitignore` 里 `dist/*` 之外单独放行了它。
**旧包必须先被新包覆盖再提交**：`git add -A` 会把 `dist/` 里的包一起带上，
包里是压缩内容（工作树 grep 扫不到），留下过期包 = 把上一版的真实串一起推上去。

> 判据补充：门禁的"全 0"只对**黑名单里写了的**值成立。黑名单在仓库外、由人维护，
> 新出现的真实人名/报表名如果没补进去，门禁不会命中——补黑名单是发布前的人工检查项，
> 别把"✅ 三处复扫全 0"当成"没有敏感信息"的证明。

### 手工步骤（脚本之外仍需人判断的部分）

```bash
cd <本项目目录>

# ① 脱敏（工作树）—— 规则替换成占位符，扩展名要覆盖全
<按黑名单替换，见上>

# ② 复扫工作树（含扩展名兜底）
grep -rIl "<黑名单逐项>" . --exclude-dir=.git --exclude-dir=__pycache__   # 必须为空

# ③ 重写历史（仅当历史里有敏感内容时）
cp -R .git /tmp/backup-$(date +%s)          # 或 tar czf
git filter-branch -f --tree-filter "<脱敏脚本>" --prune-empty -- --all
rm -rf .git/refs/original && git reflog expire --expire=now --all && git gc --prune=now
#   ⚠️ filter-branch 会同时改写 refs/remotes/*，之后强推要用**显式 lease**：
#   git push --force-with-lease=<分支>:<远端真实SHA> origin <分支>

# ④ 逐 blob 复扫（文本 + 历史里的二进制）
<对每个 rev-list blob 跑黑名单；zip 要解包>

# ⑤ 打包（分发包入库，其他 dist 产物忽略）
tools/build_skill.sh  # 包含 docs；使用 Python zipfile 正确标记中文文件名为 UTF-8

# ⑥ 解包复扫包内文本（zip 是压缩的，必须解开扫）
rm -rf /tmp/pk && mkdir -p /tmp/pk && unzip -q dist/fanruan-v10.skill -d /tmp/pk
grep -rIl "<黑名单逐项>" /tmp/pk      # 必须为空

# ⑦ 功能验证 + 同步安装态
PYTHONPATH=src python -m pytest tests/ -q
rsync -a --delete --exclude='.git' --exclude='__pycache__' --exclude='.pytest_cache' \
      --exclude='.DS_Store' --exclude='frcli.egg-info' --exclude='dist' ./ <安装态目录>/
```

## 五、2026-09 的教训（都真实发生过）

| 教训 | 后果 |
|---|---|
| 只改工作树、不洗历史 | 10 个提交里全是真实姓名/工号/域名 —— 一公开即泄露 |
| 只扫文本、忘了 `.skill` 是 zip | 每个历史包里有 83~101 处敏感串，且**复扫显示为 0（假阴性）** |
| 只扫 `.md/.py`，漏了 `.cpt/.csv/.html` | `.cpt` 里的 `<DatabaseName>` 带着真实连接名 |
| 教程/说明文档里"举例"写了真实值 | 连说明文件本身都要再洗一遍 |
| 残留旧版未脱敏包在 `dist/` | 按习惯复制到发布仓库 = 泄露 + 发错版本 |
| 生成器不带参数直接跑 | 把清单文件覆盖成空壳（已加护栏：空清单拒绝覆盖） |
