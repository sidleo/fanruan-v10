## 1. §1 分组报表 + 组内小计 + 总计 + 占比

### 1.1 照最终版配方逐条复现（可复制 ✅）

做法：`report new` → `report dataset --add` → **`report table … --mode group`** → D3 占比公式 →
A4/C4 小计（`--expand-left A3`）→ A5/C5 总计。8 条命令全部 `status: ok`、exit 0。

真实逐格输出（`/tmp/pv/final1.xlsx`，渲染后坐标；csv 逐格一致）：

```
dims: A2:D10   merged: ['A3:A5', 'A7:A8']
2  ['中心', '销售员', '金额', None]
3  ['SC04', '张三', 100, 0.0667]
4  [None,   '李四', 200, 0.1333]
5  [None,   '王五', 300, 0.2   ]
6  ['小计', None,   600, None  ]
7  ['SC03', '赵六', 400, 0.2667]
8  [None,   '钱七', 500, 0.3333]
9  ['小计', None,   900, None  ]
10 ['总计', None,  1500, None  ]
```

程序化比对文档 §1「实测导出」表：**9 行全部逐格一致**（数值容差 1e-3）。
csv 通道同样一致（占比列文本 `6.7%/13.3%/20.0%/26.7%/33.3%`）。
⇒ **可复制**。文档 §1 结论（`C3[!0]` 是整列合计、小计靠显式左父格、合计行自动下移、合并引擎自动做）全部成立。

### 1.2 对抗：分组行数/数据形态变化

| 变体 | 做法 | 真实逐格输出 | 结论 |
|---|---|---|---|
| **0 行** | SQL 加 `from (select 1) t where 1=0` | 表头行在、无明细行；占比格单独渲染 `0.0%`；`小计 0`、`总计 0`；版面不崩 | ✅ 不报错、版面保留；🟡 占比格无数据也出 `0.0%`（观感瑕疵） |
| **1 行** | 只留 SC04/100 | `100 / 100% / 小计 100 / 总计 100` | ✅ 正确 |
| **重复键** | SC04/张三 100+200、SC03/李四 400 | `A3:A4`+`B3:B4` 合并；占比 14.3%/28.6%/57.1%（分母 700 ✓）；小计 300/400；总计 700 | ✅ 占比与小计均正确 |
| **amt 含 NULL** | 中间一行 `cast(null as int)` | 金额格=空、**占比格=0.0%**；小计 100（NULL 不计）、总计 500、占比 20%/80% | ✅ 数值正确；🟡 同一行"空 vs 0"不统一 |

⇒ §1 的占比公式 `=C3/SUM(C3[!0])` 在**行数/重复键/NULL** 下均保持正确（分母始终是整列合计）。

### 1.3 对抗：多级分组时小计挂哪一级（Lead 指定复核项）

做法：`中心(A3,分组) × 销售员(B3,分组/列表)`，第 5 行挂 `--expand-left B3`（销售级）、
第 6 行挂 `--expand-left A3`（中心级）、第 7 行 `=SUM(C3)`。

真实输出（xlsx=csv）：
```
2 ['中心','销售员','金额']
3 ['SC04','张三',100]     5 ['销售小计',None,100]
6 [None,'李四',200]        8 ['销售小计',None,200]
9 [None,'王五',300]       11 ['销售小计',None,300]
12 ['中心小计',None,600]   ← 挂 A3 正确
13 ['SC03','赵六',400] … 20行 ['总计',None,1500]
```

- ✅ `--expand-left A3` = **挂中心级**（每个中心一行，600/900 正确）；`--expand-left B3` = **挂销售级**（每个销售员一行）——两级可同时存在、互不干扰。
- ✅ `=SUM(C3)` 在**分组模式**下区间仍自动伸展：总计 = 1500 = 明细和。
- 🟠 **内层小计每组前多出一个空行**（xlsx 行 4/7/10 全空，csv 同为 `,,`）。
  单独验证：只有 `--expand-left B3` 时照样多一行；标签放 A 列或 B 列都一样（4 个变体复现）。
  **挂最外层维度列（§1 原配方的 A3）时没有这个问题。**
  ⇒ 配方集应写：多级分组的**内层**小计当前会多一个空行；要组内小计优先挂最外层维度，或直接把小计做进 SQL。

| 模式 | 东区/张三 的 A 格 | 行汇总 | 总计行 A | 缺失组合 | 导出状态 |

⇒ 文档三条结论全部成立：① 默认模式**静默出错值**（无任何报错，xlsx=csv 都一样）；
② `--agg sum` 能修数值但把"没有数据"变成 `0`；③ 正确姿势是 SQL 先聚合。
🔴 级别理由：值格是拼接字符串、总计与真值差 50，两张通道都 `status: ok`（证据：`§2-同一交叉点多记录-*.xlsx`）。

### 2.4 列序来源与 `<SortFormula>`（**文档"未实测"本轮闭环**）

| 做法 | 真实列序 |
|---|---|
| 数据出现序 C,A,B（SQL 无 order by） | `C,A,B` ← **列序 = 数据首次出现顺序**（文档坑 3 前半句 ✅） |
| 同一批数据 SQL 加 `order by prod` | `A,B,C` ⇒ **SQL 顺序能影响列序**（文档坑 3 后半句 ✅） |
| 下模板 → 在列维度 DSColumn 里插 `<Complex order="1" reselect="true"/>` | `A,B,C`（**只加 order 就按本格值升序**） |
| `order="1"` + `<SortFormula><![CDATA[$$$]]></SortFormula>` | `A,B,C`（等价于升序） |
| `order="1"` + `<SortFormula><![CDATA[if($$$="B",1,if($$$="A",2,3))]]></SortFormula>` | **`B,A,C`**（自定义序生效，值与标签不串位：东区/张三 = B3/A2/C1） |

⇒ 结论（可直接写进文档）：**`<SortFormula>` 真的能控制交叉表列序**，位置在 `DSColumn` 的 `<RG>` 之后、
`<Parameters>` 之前（顺序 `Attributes→Condition→Complex→RG→SortFormula→Parameters` 与语料一致）；
`<Complex order="1">` 本身已按本格值排序。**CLI 不暴露这个开关**，只能
`report download → 改 XML → report upload`（模板片段证据：`docs/验证/证据/配方复现/§2-SortFormula-可用的模板片段.cpt`）。
另测：手工加的 `<SortFormula>` **不会被后续 `report cell` 写操作抹掉**（对同一格再加 `--num-format` 后列序仍为 A,B,C，XML 里 `SortFormula` 仍在）。

### 2.5 角标 `--label` 静默消失 + **单元格文本里的反斜杠 = 静默空值** 🔴

文档 §2 的配方正是 `--label "地区\\销售员/产品"`（bash 双引号后 CLI 收到**单个反斜杠**），
而文档自己的实测输出里 `A3 = None` —— 两边一致，但**没人发现角标其实渲染空了**。独立定位过程：

| 写入 A3 的值（CLI 收到） | 模板里存的是什么 | 导出渲染 | 结论 |
|---|---|---|---|
| `CORNER` | `CORNER` | `CORNER` | 正常 |
| `地区销售员/产品`（无反斜杠） | 同左 | 原样 | 正常 |
| `地区\销售员/产品`（**单**反斜杠） | **原样存**（CLI 不转义） | **空（None）** | 🔴 静默丢字 |
| `地区\\销售员/产品`（双） | 原样 | `地区\销售员/产品` | `\\`→`\` |
| `a\b` | 原样 | `a?` | `\b` 被当转义 |
| `a\tb` | 原样 | `a<TAB>b` | `\t`→制表符 |
| `x\y` / `C:\data\file` / 单个 `\` | 原样 | **整格空** | 🔴 非法转义 ⇒ 整格消失 |

- **服务端把单元格静态文本按转义序列解读**：`\\`→`\`、`\t`→TAB；非法转义（`\y`/`\d`/末尾 `\`）⇒ **整格渲染为空**，`status: ok`、无任何提示。
- **数据侧不受影响**：数据集里 `'a\b'`、`'C:\data'`、`'a\tb'` 导出的码点是原样的（实测 4/4），
  所以这是**静态文本/标签**独有的坑。
- 修复建议：文档 §2 角标示例改成不含反斜杠的写法（如 `地区/产品`），并在 §0/§2 加"反斜杠"坑：
  **要写 `\` 必须写两个**；写单反斜杠会造成整格静默消失。
- CLI 侧无需改（它原样落盘是正确的；`tests/test_patterns_repro.py::test_set_value_keeps_backslash_verbatim` 钉住这一侧）。

## 3. §8 公式函数

### 3.1 基线复现（可复制 ✅）

数据 `SC04 100/200、SC03 300、SC05 50/50`（合计 700），8 条公式命令全部 exit 0：

```
2 ['中心','金额','占比','序号','累计','环比','去重中心数','总额校验']
3 ['SC04',100, 14.3%, 1, 100,   0.0%,  3, 700]
4 ['SC04',200, 28.6%, 2, 300, 100.0%,  3, 700]
5 ['SC03',300, 42.9%, 3, 600,  50.0%,  3, 700]
6 ['SC05', 50,  7.1%, 4, 650, -83.3%,  3, 700]
7 ['SC05', 50,  7.1%, 5, 700,   0.0%,  3, 700]
```
xlsx 与 csv 逐格一致（csv 占比/环比为格式化文本）。⇒ **文档 §8 的六个公式结论可复制。**

### 3.2 坑 1 `SEQ()` 内联：**版面相关的静默错**（文档结论缺条件）🟠

文档说：`=SUM(SLICEARRAY(B3[!0],1,SEQ()))` 实测**每行都得 700**（整列合计），必须改成引用
`D3`（另一个 `SEQ()` 格）。实测**两种版面结果不同**（各跑 2 轮稳定）：

| 版面 | I3 内联 `SEQ()` 的结果（5 行） | 与文档 |
|---|---|---|
| 版面里**另有** `D3=SEQ()`（= 文档样例的版面） | **700,700,700,700,700** | 文档 ✅ |
| 版面里**没有任何** `SEQ()` 格 | **100,300,600,650,700**（正确的累计！） | 文档 ❌ |

⇒ 结论要条件化：**`SEQ()` 写在公式里是否生效取决于版面里是否存在另一个 `SEQ()` 格**；
两种情况下都不报错、都 `status: ok`。安全写法仍然只有一种：**单独一格 `=SEQ()`，公式里引用该格**。
（🔴 风险等级：同一公式换版面结果不同且无提示；因文档已给安全写法，文档侧记 🟠。）

### 3.3 坑 2 `RANK`（复现 ✅）

`J3 = =RANK(B3,B3[!0])` → xlsx 每行 `#NAME?`，csv 尾部同样输出 `#NAME?`；`report datasets` **干净**（不报错）。
⇒ 文档结论成立：函数名注册但求值失败，**组内排名请写在 SQL 里**。并列排名因此无从谈起。

### 3.4 坑 5 `SLICEARRAY`（文档有误 ❌）

- 文档：「`SLICEARRAY(B3[!0],1,2)` = 前两个 = 300（100+200）✓」。
- 实测：单元格里只写 `=SLICEARRAY(B3[!0],1,2)` → 渲染成 **字符串 `'100,200'`**（数组直接落格被拼接）；
  写成 `=SUM(SLICEARRAY(B3[!0],1,2))` 才是 **300**。
⇒ 文档把"函数语义（1 基闭区间）"与"格子里看到的值"混在一行。建议改：
`SLICEARRAY(arr,1,2)` 返回**数组**（1 基、闭区间），落格会拼成 `100,200`；要数值请套 `SUM`。

### 3.5 其余的坑（复现 ✅）与补充

- `INDEX(B3[!0],2)` → **`2`** ✅（不是数组下标）。
- `report datasets` 对坏函数名 **会**报 `no function found: X`（文档 §8 坑 3 的排查入口成立；我这轮用它验证过装置）。
- 除零/空值补充实测：`=1/0` → `#DIV/0!`（三行都显式报错）；`=B3/0` 在 B=0 那行得 **0**（`0/0=0`，不报错、显式可见但易误读）；
  引用空格的 `=G3+1` → `1`（空格当 0）。⇒ 除零不静默，但 **`0/0=0`** 会让"分母为 0"的真相被掩盖，做占比列时要注意。

## 4. §3 条件属性 `<Highlight>` 对抗

### 4.1 文档三条规则原样（可复制 ✅）

规则：`ROW()%2=0:bg=#F2F2F2`（宽，放第一）→ `v<100:bg=#C6EFCE,fg=#006100` → `v>300:bg=#FFC7CE,fg=#9C0006,bold`（挂 C3），
另把隔行灰挂在 A3:B3。数据 100/350/500/80/260。openpyxl 读 `fill.fgColor.rgb` / `font.color.rgb` / `font.bold`：

```
C3: 100  bg=-       fg=-       bold=0     ← 100 不小于 100、不大于 300、ROW()=3 奇数
C4: 350  bg=FFC7CE  fg=9C0006  bold=1     ← >300 命中，且**盖掉**同一行的隔行灰

（CLI 把字色并进 `<FRFont foreground=…>` 的修正有效；XML 侧断言见
`tests/test_patterns_repro.py::test_highlight_rule_order_is_priority_order`）。

### 4.2 规则顺序 = 优先级（后覆盖前）✅

把宽规则（隔行灰）挪到最后：C4 的底色变成 `F2F2F2`（条纹盖掉阈值红），但**字色 `9C0006` 与加粗仍在**
⇒ "后覆盖前"成立，且只覆盖被显式设置的动作（`bg` 被盖、`fg/bold` 保留）。文档坑 2 正确。

### 4.3 隐藏整行：**xlsx 消失、csv 仍在**（🔴 双通道分歧）

做法：数据行 3..7（amt 在 C），`report highlight --at A3:C3 --rule 'v<100:rowheight=0' --apply`。

| 通道 | 真实输出 |
|---|---|
| xlsx | `dims A2:C6`，**80 那一行整行消失**（100/350/500/260） |
| csv | `SC04,张三,100 / SC04,李四,350 / SC03,王五,500 / **SC05,赵六,80** / SC05,钱七,260` —— **80 还在** |

⇒ 文档 §3 只说"导出 xlsx 里 80 那一行整行消失"（严格讲没错），但**没写 csv 不一致**。
**而作者自己的样例 `patterns/r3c_hide_row.cpt` 同样如此**（xlsx `dims A3:B7` 无 80，csv 第 6 行仍有 `SC03,80`）。
⇒ 按团队"双通道对"的纪律，这是必须写进文档的坑：**"隐藏整行"是渲染层效果，只在 xlsx/pdf 等版面通道生效，
csv（数据通道）照样输出该行**；用 csv 验收的人会以为隐藏失败，用 xlsx 验收的人会以为数据不存在。
（证据：`docs/验证/证据/配方复现/§3-隐藏整行-*`）

另测：区域**不含数值列**时（`--at A3:B3`，全是文本）规则静默无效（`v<100` 对字符串为假）——
文档 §3 的 `--at A4:B4` 示例只对"金额列在区域内"的版面成立；**照抄到其它版面会静默什么都不发生**。

## 5. §4 多数据集关联取数

做法：`ds1` 三个中心 + 多一个无匹配中心 `SC07`；`ds2` 含 `SC04×2 / SC03 / SC05 / SC09`。

```
2 ['中心','名称','SUM(select)','select明细','COUNT','ds2.sum(错函数)','绝对$A$3']

   （ds2 的 SC09 不出现 ⇒ 以 ds1 行为准，等价 left join ✓）

## 6. §5 参数联动过滤

### 6.1 基线（可复制 ✅）

默认导出：`A1='金额 >= 100'`、`SC04/100`、`SC03/300`（`SC05 50` 被过滤）；
`--params '{"min_amt":200}'`：`A1='金额 >= 200'`、只剩 `SC03/300`。与文档一致。

### 6.2 空串 / 非法值 → **显式报错**（不是静默）

`--params '{"min_amt":""}'` 与 `'{"min_amt":"abc"}'` 都拿到平台出错页，`frcli export` 报 `EXPORT_ERROR`，
出错页 `detail-message` 写明 `11300001 数据集 [ds1] 配置错误 … Syntax error … where amt >= ` /
`Could not resolve column/field reference: 'abc'`。⇒ **不静默、可定位**（这是好行为）。

### 6.3 无默认值：公式侧静默空串 ✅、SQL 侧报错（文档结论要加条件）

| 场景 | 真实输出 |
|---|---|
| 参数只用在单元格公式（`="金额 >= " + $min_amt`），无默认值、不传参 | 导出 ok，渲染 `'金额 >= '`（**静默空字符串** ← 文档坑 2 ✅） |
| 参数用在 SQL 值位置（`where amt >= ${min_amt}`），无默认值、不传参 | **导出失败**：11300001（SQL 变成 `amt >= `） |
| 公式里显式判空 `IF($c == "", …)` | `'参数为空'` ✅（说明未传参确实等于空串） |

⇒ 文档坑 2「静默空字符串」只对**公式/文本**用法成立；**用在 SQL 里会直接报错**。建议补一句条件。

### 6.4 🔴 配方坐标错：过滤列挂 C3（表头行）会与表数据错开

文档 §5 配方：`report table … --at A3 --header` 之后写 `report cell … --at C3 --bind ds1.amt --ds-filter …`。
按 §0 规则 2，`--at A3 --header` 的**数据行是 A4**，C3 是**表头行**。实测后果：

```
默认导出（挂 C3）：dims A1:C6  merged ['A1:B1','A3:A4','B3:B4']
3 ['中心','金额', 100]      ← C 列的取值落在表头行
4 [None,  None,  300]
5 ['SC04', 100,  None]      ← A/B 的表数据被挤到 5/6 行
6 ['SC03', 300,  None]
```
即：**过滤列的取值与它所属的行错开一~两行**（表头被拉伸合并 `A3:A4`）。
把同一条命令改成 `--at C4`（数据行）后：
```
dims A1:C5  merged ['A1:B1']
3 ['中心','金额', None]
4 ['SC04', 100, 100]        ← 对齐
5 ['SC03', 300, 300]
```
⇒ 文档 §5 配方应把 `--at C3` 改成 `--at C4`；并且文档自己的样例 `patterns/r5_params.cpt`
**根本没有这一列**（导出 `dims A1:B5`，只有中心/金额两列）⇒ **配方与样例不一致**，
样例无法证明该步可用。严重级 🔴：导出 `status: ok`，版面错位不报错。
