# 数据集预览（report preview）验证报告

> 验证者：`verifier`（teammate，独立开发/验证分离）｜日期：2026-10-24｜仓库版本：fanruan-v10 0.10.17
> 环境：`<FineReport 平台 10.0.0>`（验证只用只读测试对象，写权限未验证；真实路径/连接名/结果值不入库）
> 被测能力：`frcli report preview`（等价 Designer 右键数据集「预览」，只读，服务端真实执行 SQL）

## 0. 结论速览

| 问题 | 结论 |
|---|---|
| 数据集能按 Designer 那样预览吗？ | **能**。`golden` 测试模板 ds1 的 5 行预览与独立通道（yh_bigdata 直查同一 Impala SQL）**5/5 行逐值一致**；34 列宽表也能返回全列 |
| 是否只读？ | **是**。命令路径只有 GET（`format=cpt` 取数据集定义）+ 远程设计 check/verify/channel（`previewTableData`），无任何写/删除/加锁调用；未设 `FRCLI_WRITE_SCOPE` 也成功；`~/.frcli/backups` 与 token 缓存无变化 |
| 参数语义与平台一致吗？ | **一致**。数据集 SQL 的 `${x}` 由 CLI 先做文本替换（与平台同名替换）；缺参数 CLI 直接报错，服务端缺参数则静默替换空串（已实测） |
| 结果编码解析可靠吗？ | **可靠**。平台自身 Java 类解码真机 payload 与本实现**79/79 字节相同**；1530 组平台编码 ASCII85 全部解码正确；cdata `]A` 6/6 一致；测试 fixture 确为平台 `XMLEncodeUtils.encodeBytesAsString` 产物 |
| 错误处理可操作吗？ | **是**。SQL 错带 `11300001`+平台原文（含 SQL）、缺参列出全名、数据集不存在列可选项、连接不存在报 `31300013`，均为 JSON error 无 traceback |
| 测试/打包/脱敏 | `700 passed, 2 skipped`；`tools/build_skill.sh --check` 工作树/包内/git 历史三处命中 0；版本三处 0.10.17 |

**首轮独立验证结论：核心通过（无 BLOCKER/HIGH）**；发现 2 个 `-f table` 展示缺陷（MEDIUM，非取数层）与若干 LOW/INFO。修复后复验见 §4。

## 1. 方法与证据口径

- **独立取数对照**（关键证据）：用 `frcli report datasets` 取模板数据集 SQL，参数做同样文本替换后，用 **yh_bigdata 直查 Impala** 取数，与预览的列名/列序/行数/逐行值对比全等。
- **解码交叉验证**：用平台 jar 的 `XMLEncodeUtils.cdataDecode` + `decodeStringAsBytes` 解真机 RowData，`encodeAscii85`/`encodeBytesAsString` 生成对照编码，并反编译 `Ascii85InputStream` 核对 `z`/末组语义；与本实现逐字节/逐值对比。
- **边界与错误**：rows=1/2/3/100/1000、`--rows 0/1001`、SQL 报错、缺参、数据集不存在、连接不存在、0 行、含 `&t;`/`&n;`/`]A`/emoji/NULL 的构造数据。
- **变异测试**：在 `/tmp` 副本里改实现（不碰仓库），确认新增测试会失败（见 §3）。
- **只读证据**：调用序列静态审查 + 运行前后 `~/.frcli/backups`、token 缓存 mtime、仓库文件清单对比。
- **脱敏**：本报告不写真实服务器/目录/连接名/组织/报表名与真实业务值；只给判据与结构性结论。

### 首轮 Findings（已处理）

| # | 严重度 | 现象 | 处理 |
|---|---|---|---|
| 1 | MEDIUM | `-f table` 34 列宽表在 80 宽终端下 rich 把列压成 0 宽：表头与行值全不可见（JSON 正常） | 宽表改**纵向布局**（列清单 + 每行 `序号. 列名 = 值`）；新增 CLI 渲染测试 |
| 2 | MEDIUM | 数据/列名里的 rich 标记被当样式解析：`[red]x`→`x`、`[b]`→空、`[/]` 触发 MarkupError 退出 | 所有动态内容用 `rich.text.Text` 包裹；新增含 `[red]x`/`[/]`/`x[y]z` 的 CLI 测试 |
| 3 | LOW | ASCII85 解码缺平台解码器的 `z`（4 个零字节）分支 | 已补 `z` 分支；用平台编码器生成的 `z~`/`z!<N~`/`zz~` fixture 做测试 |
| 4 | LOW | 序列化骨架测试缺「patch 后仍可被 JavaReader 读回字段」的往返断言（变异 M3a 未抓住） | 新增往返测试：`build_table_data_blob` → `jser.JavaReader` 读 database/query 字段 == 入参 |
| 5 | LOW | §6.25 超时口径只写 `FRCLI_RD_TIMEOUT`，漏了第一跳 `report datasets` 吃 `FRCLI_TIMEOUT` | 文档改为「两跳都要按需调大」 |
| 6 | LOW | 「标准 ASCII85 补 `u` 会解错尾字节」措辞过强（平台编码器零填充，不产生差异） | 措辞改为「镜像平台解码器实现细节」 |
| 7 | LOW | 64KB 报错未点名 SQL/上限口径 | 报错点名「数据集预览的 SQL/连接名」与 Java 字符串上限 65535；`preview()` 增加 mark/payload 形态校验（非 XML 直接报错，不静默空表） |

## 5. 未覆盖/已知限制

- **无远程设计授权账号**的权限失败路径未真机构造（测试账号有权限）；代码按远程设计通道既有错误处理走。
- **非 SQL 数据集**（服务器数据集/存储过程/内建数据集）真机报错文案仅单测覆盖。
- **`InvalidClassException` 兼容分支**无法真机触发（需换平台大版本）。
- `--params` 的 bool/非标量值在平台侧的语义只做代码/文档检查。
- `z` 分支在真实行数据中未自然触发（概率极低；用平台编码器 fixture 覆盖语义）。
