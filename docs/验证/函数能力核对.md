# 函数能力核对

核对日期：2026-10-30。对象为 FineReport 10 安装包中的函数实现、随包公式帮助、
官方 10.0 文档，以及当前工作区的 `frcli` 源码。

## 覆盖结论

`report cell --set-formula` 原本能够写入任意公式文本，函数计算交给 FineReport 引擎。
需要补充的是函数检索、基础语法检查和参数/控件公式默认值的写入能力。

| 范围 | 结果 | 证据边界 |
| --- | --- | --- |
| `fine-core-10.0.jar` 大写函数实现类 | 167 个，目录名称集合完全匹配 | 证明实现存在，不证明全部可在任意上下文求值 |
| `fine-report-engine-10.0.jar` 大写函数实现类 | 13 个，目录名称集合完全匹配 | 包括层次坐标等依赖报表上下文的实现 |
| 官方数据集方法 | `select`、`group`、`value` 3 条 | 数据集名为占位符；参数顺序和使用位置分别说明 |
| 随包函数目录 | 共 183 条，均有调用速查与来源 | 速查不列举所有可选形式，不作为插件白名单 |
| 单引号及引号转义 | 原生词法器接受 3 个对应样例 | 词法层验证，不是完整报表计算 |
| `RANK` 独立实现调用 | 数组 `[1,5,3]` 中的 5，降序为 1、升序为 3 | 不涉及层次坐标、报表扩展或导出 |
| `SUM` 独立实现调用 | `[1,5,3]` 求和为 9 | 不涉及数据集或报表上下文 |
| 公式默认值 | XML 结构往返、作用域隔离与幂等性通过 | 没有服务端模板写入或渲染验收 |

函数与来源入口见 [函数使用手册](../../references/formulas.md)。
`TOTEXT` 的实现按名称读取 `ProductConstants` 常量，不能从名称推断为普通文本转换；
`CIRCULAR` 是按前期格子循环引用累计，不能当作同期比例函数。

## 样本与复核方法

只读核对 `com/fr/function/[A-Z][A-Z0-9_]*.class` 的名称集合，与
`src/frcli/function_catalog.py` 按 `source_jar` 分组的记录逐项比较。
调用签名来自随包帮助，帮助未说明的部分继续检查 `run/call` 字节码。

本轮两个实现 jar 的 SHA256：

| 文件 | SHA256 |
| --- | --- |
| `fine-core-10.0.jar` | `17301eb85c0d9a779c6c6081567f4123e34fc2adb4b26fb4080ff9d7d94c150f` |
| `fine-report-engine-10.0.jar` | `d5909b5109c3c4758906921159b8fcca58ca3bbb65dad00e471f0ebe7c20a19f` |

JDK 复核入口：

```bash
javap -c -p -classpath '<安装目录>/webapps/webroot/WEB-INF/lib/*' \
    com.fr.base.DefaultNameSpace com.fr.parser.FRLexer \
    com.fr.function.RANK com.fr.function.MAPARRAY com.fr.function.CIRCULAR
```

原生词法器样例为 `SUM([1,2])`、`IF(1=1,'a)b','c')` 和
`CONCATENATE("a\"(b","c")`。它们用于证明字符串内的括号与转义引号不会参与括号配对。
