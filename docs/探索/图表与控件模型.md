## 0. 两条必须先纠正的旧认知

| 旧写法（本仓库早前的猜测） | 实测真相 | 证据 |
|---|---|---|
| `<O t="CC">` = "跨列/占位（合并区内的续格）" | **`CC` = `com.fr.chart.chartattr.ChartCollection`，即"图表单元格"**。语料 672 个 `<O t="CC">` **全部**含 `<Chart>` | `com.fr.chart.module.ChartModule.init()` → `StableFactory.registerXMLDescription("CC", new ChartCollection())` |
| `<Embed>` = "嵌入的内容（图表/子报表/HTML）" | **`<Embed position="1"/>` 是工具栏位置标记**，在 `ToolBars/ToolBarManager/Location` 里，与"嵌入内容"无关 | 语料 3 个真实片段（§C） |

**通用教训**：`<O t="X">` 的 `X` 是 `StableFactory` 里的**短名注册表**，不是类名缩写习惯。
`GeneralXMLTools.readObject(reader)` 取 `t` 属性 → `Object_Tokenizer.tokenizerObject(reader, false, t, null)`
（`com.fr.general.xml.GeneralXMLTools:301-308`）。**遇到不认识的 `t=` 先去 jar 搜 `registerXMLDescription("X"`，别猜。**

# A. 图表 `<Chart>`

## A.1 容器：图表单元格是 `<O t="CC">`

```
<C c="3" r="1" cs="5" s="1">
<O t="CC">
  <LayoutAttr selectedIndex="0"/>            ← 多图表时的选中项
  <ChangeAttr …/>                            ← 可选：轮播/自动刷新
  <Chart name="默认" chartClass="com.fr.plugin.chart.vanchart.VanChart">
    <Chart class="com.fr.plugin.chart.vanchart.VanChart" …>   ← 真正的图表对象
      …
    </Chart>
  </Chart>
</O>
<PrivilegeControl/>
<Expand/>
</C>
```

`com.fr.chart.chartattr.ChartCollection` 就是 `CC`：
- `readXML`（第 249 行）：`LayoutAttr` → `selectedIndex`；`changeConfigAttr.readXML`；`Chart` →
  `StableUtils.classForName(reader.getAttrAsString("chartClass", Chart.class.getName())).newInstance()`
- `writeXML`（第 302 行）：`startTAG("LayoutAttr").attr("selectedIndex", …)`，然后
  `startTAG("Chart").attr("name", …).attr("chartClass", provider.getClass().getName())`

⇒ **外层 `<Chart name= chartClass=>` 是"命名容器"，内层 `<Chart class=>` 才是图表本体**；
`chartClass` 缺省 = `com.fr.chart.chartattr.Chart`。语料里 `<Chart>` 共出现 **538 个模板**，
类分布：无 class（外层容器）538、`VanChart` 514、`com.fr.chart.chartattr.Chart` 4。

### A.3.4 数据怎么接（两种模式，互斥）

**模式一：数据集数据源（推荐实现，VanChart 默认）**

```xml
<ChartDefinition>
<OneValueCDDefinition seriesName="产品类型" valueName="销量"
                      function="com.fr.data.util.function.SumFunction">
<Top topCate="-1" topValue="-1" isDiscardOtherCate="false" isDiscardOtherSeries="false"
     isDiscardNullCate="false" isDiscardNullSeries="false"/>
<TableData class="com.fr.data.impl.NameTableData"><Name><![CDATA[ds1]]></Name></TableData>
<CategoryName value="销售员"/>
</OneValueCDDefinition>
</ChartDefinition>
```

- `com.fr.chart.chartdata.OneValueCDDefinition`（`XML_TAG = "OneValueCDDefinition"`，`DEFINITION_TYPE = "SingleColumnDefinition"`）
  - `writeXML`（第 169 行）写 `seriesName` / `valueName` / `function` 三个属性；`readXML`（第 185 行）同
  - 父类 `NormalTableDataDefinition` 负责 `<TableData class="com.fr.data.impl.NameTableData"><Name>ds1</Name></TableData>`
    与 `<CategoryName value="销售员"/>`
- 语义：`seriesName` = 系列名（图例名）、`valueName` = 数值列、`CategoryName@value` = 分类列、
  `function` = 聚合函数（同 `com.fr.data.util.function.*`，见 `references/cpt-features.md` §1.2）
- **`NameTableData` 就是指名引用模板里的 `<TableData name="ds1">`** —— 与单元格数据设置同一套数据集
- 多系列用 `MoreNameCDDefinition`（266 个模板）+ `<ChartSummaryColumn>`
- 各图型的数据定义类型（`DefinitionXmlHelper.readOldChartDefinition`，第 71 行 —— **标签名 → 类的完整映射表**）：

  | 标签 | 类 |

  | `OneValueCDDefinition` | `OneValueCDDefinition` |
  | `MoreNameCDDefinition` | `MoreNameCDDefinition` |
  | `NormalReportDataDefinition` / `ReportDataDefinition` | `NormalReportDataDefinition` |
  | `MeterTableDefinition` / `MeterReportDefinition` | 仪表盘 |
  | `ScatterTableDefinition` / `ScatterReportDefinition` | 散点 |
  | `StockTableDefinition` / `StockReportDefinition` | 股价 |
  | `BubbleTableDefinition` / `BubbleReportDefinition` | 气泡 |
  | `GanttTableDefinition` / `GanttReportDefinition` | 甘特 |
  | `MapSingleLayerTableDefinition` / `MapSingleLayerReportDefinition` | 单层地图 |
  | `MapMoreLayerTableDefinition` / `MapMoreLayerReportDefinition` | 多层地图 |
  | `GisMapTableDefinition` / `GisMapReportDefiniton`（注意拼写） | GIS 地图 |
  | `SeriesListDefinition` | 兼容老写法 → `NormalReportDataDefinition` |

  语料频次（模板数）：`MoreNameCDDefinition` 266、`OneValueCDDefinition` 133、`SeriesDefinition` 66、
  `NormalReportDataDefinition` 65、`VanMapDefinition` 52、`CustomDefinition` 34、`BubbleTableDefinition` 34、`VanGanttDefinition` 20…

# B. 参数面板控件 `<Widget>`

## B.0 `<Widget>` 一个标签，三种完全不同的用途

`<Widget>` 出现在 **746 个模板**，但**上层容器不同，语义完全不同**：

| 上层路径 | 是什么 | 模板数 |
|---|---|---|
| `ReportWebAttr/{WebWrite,WebPage,WebView}Content/ToolBars/ToolBarManager/ToolBar/Widget` | **工具栏按钮** | 416 |
| `Report/CellElementList/C/Widget` | **填报控件**（格子里放控件） | 342 |
| `ReportParameterAttr/ParameterUI/Layout/…/InnerWidget` | **参数面板控件**（我们最关心的） | 289 |

**三者写法不同**：工具栏按钮与填报控件是 `<Widget class="…">` 直接子元素；
**参数面板里真正的控件在 `<InnerWidget class="…">`**，外面套一层 `<Widget class="…WAbsoluteLayout$BoundsWidget">`。
`<InnerWidget>` 是 `Widget.readXML` 之外的容器协议（`WAbsoluteLayout$BoundsWidget`）。

## B.3 怎么绑定模板参数（**关键**：控件名 = 参数名）

**结论：参数面板里控件的 `<WidgetName name="X">` 的 `X` 就是模板参数名**（不是别名字段）。

jar 证据（`com.fr.form.main.parameter.FormParameterUI`）：

```java
// 第 255 行 setParameterValueFor_7_0_Version(Parameter[] parameterArray)
Widget widget = this.getWidgetByName(parameterArray[i].getName());   // ← 用参数名查控件

// 第 85 行 createDefaultParameterUI(Parameter[] parameterArray, …)
Label label = new Label();
label.setWidgetValue(new WidgetValue(parameter.getName()));
label.setWidgetName("label" + n);          // 标签控件名是 labelN
fieldEditor.setWidgetName(parameter.getName());   // ← 编辑器控件名 = 参数名
wHorizontalBoxLayoutArray[n / n2].addWidget(fieldEditor);
```

语料统计（289 个带参数面板的模板）：其中 **132 个同时声明了模板参数**，
其中 **111 个（84%）参数面板里有控件的名字命中声明参数名** —— 与 jar 结论一致。
反例都是"控件名 ≠ 任何声明参数"的情况（如控件 `day`、声明参数 `order`），
说明**参数可以在运行时传入而不必声明**（与 `references/cpt-authoring.md` §7.2 的结论一致）。

**默认值写在哪里**：控件的 `<widgetValue><O><![CDATA[…]]></O></widgetValue>`
（语料 564 个模板含 `widgetValue`）。**注意与 `<ReportParameterAttr>` 里是否有 `<Parameters>` 声明无关** ——
`GettingStarted.cpt` 的 `ComboBox` 名为 `地区`、`widgetValue` = `华东`，而 `ReportParameterAttr` 里**没有** `<Parameters>`。

**控件自己的数据字典**（下拉框的选项来源，按 `<Dictionary class>` 统计模板数）：
